Semantic tags

Semantic tags are how you tell Apple Wallet what your pass means — not just what it looks like. Add them, and iOS turns a static ticket into something the phone understands: it knows when to leave, where the venue is, what seat you're in, and when the show starts.

In shortThey're an optional semantics block in your pass. Everything here is additive — add the tags that fit your event, skip the rest. No tag ever breaks a pass by being absent.

What are semantic tags

A normal pass is just pixels — text and images Wallet draws on a card. It has no idea that “8:00 PM” is a start time or that a string is a street address.

Semantic tags attach machine-readable meaning to those values. Once Wallet knows eventStartDate is the start and venueLocation is the place, it can offer things you never had to build: a Lock Screen “time to leave,” a tap-to-map, a live countdown, a “silence your phone” nudge.

Same card. Suddenly intelligent.

pass.json
{
  // ...your normal pass fields...
  "semantics": {
    "eventName": "Twilight Tour",
    "eventStartDate": "2026-07-14T20:00-07:00",
    "venueName": "The Fillmore"
  }
}

Without semantics

  • A pretty card in Wallet
  • No Lock Screen suggestions
  • No map, no countdown
  • Wallet guesses, often wrong

With semantics

  • “Leave by 7:15” on the Lock Screen
  • Tap the venue → Apple Maps
  • Live “Starts in 2h” countdown
  • Clean, correct, automatic

How to add them

Put a semantics dictionary at the top level of your pass. Keys are the tag names below; values are plain strings, numbers, dates, or small objects.

Three rules cover almost everything:

1. Dates include a time zone. Use ISO 8601, e.g. 2026-07-14T20:00-07:00.
2. Money and places are objects — see Object shapes.
3. Only send real values. An empty string is worse than a missing key.

semantics
"semantics": {
  "eventStartDate": "2026-07-14T20:00-07:00",
  "totalPrice": {
    "amount": "150.00",
    "currencyCode": "USD"
  },
  "venueLocation": {
    "latitude": 37.7840,
    "longitude": -122.4330
  }
}

The 6 essentials

If you add nothing else, add these. They unlock the features people actually notice.

TagWhat it does
eventNameNames the event everywhere iOS references it.
eventStartDatePowers the countdown and “time to leave.” The single highest-value tag.
eventEndDateTells Wallet when to stop showing the pass as live.
venueNameLabels the place on the ticket and in the guide.
venueLocationEnables tap-to-map and location-based Lock Screen relevance.
eventTypeTells Wallet what kind of event this is, so it tailors the layout.
the-essentials.json
"semantics": {
  "eventType": "PKEventTypeLivePerformance",
  "eventName": "Twilight Tour",
  "eventStartDate": "2026-07-14T20:00-07:00",
  "eventEndDate": "2026-07-14T23:00-07:00",
  "venueName": "The Fillmore",
  "venueLocation": { "latitude": 37.784, "longitude": -122.433 }
}
TipeventType is one of: PKEventTypeLivePerformance, PKEventTypeMovie, PKEventTypeSports, PKEventTypeConference, PKEventTypeConvention, PKEventTypeWorkshop, PKEventTypeSocialGathering, or PKEventTypeGeneric.

Where tags show up

This is the part other docs leave out. A tag lands in one of four places — and some are invisible on purpose. Throughout this page each tag is labelled with where you'll see it.

Pass face the front of the card Event Guide the detail screen behind the pass Lock Screen suggestions & live activity Metadata no UI — powers behavior & Siri
NotePlacement is Wallet's call, not yours — these labels are the typical surface for each tag. Apple composes the final layout from everything you send.

Sports

Add when eventType is PKEventTypeSports. Team abbreviations render right on the artwork (“LAR vs SF”).

TagWhat it does
sportNameThe sport, e.g. Football.
leagueName · leagueAbbreviationFull and short league name; the abbreviation shows in the header badge.
homeTeamName · homeTeamAbbreviation · homeTeamLocationHome team — full name, code on the artwork, and city.
awayTeamName · awayTeamAbbreviation · awayTeamLocationAway team — same three.

"eventType": "PKEventTypeSports",
"sportName": "Football",
"leagueAbbreviation": "NFL",
"homeTeamAbbreviation": "LAR",
"homeTeamLocation": "Los Angeles",
"awayTeamAbbreviation": "SF",
"awayTeamLocation": "San Francisco"

Admission & seating

What the holder is entitled to — the footer of the ticket. Seats are an array; add one object per seat.

TagWhat it does
admissionLevel
Pass face		Tier of access — “General Admission,” “VIP.”
attendeeName
Pass face		Who the ticket admits. The fallback value when no seat/admission is set.
seats[]
Pass face		Seat detail — seatSection, seatRow, seatNumber render as footer columns; seatAisle, seatLevel add more.

"attendeeName": "Jane Smith",
"seats": [

    "seatSection": "A",

  }

Object shapes

A few tags take small objects instead of a plain value. Here they are, once.

Money — CurrencyAmount

Used by totalPrice and balance. amount is a string; currencyCode is ISO 4217.

Place — Location

Used by venueLocation. Both values are decimal degrees.

Seat — Seat

An entry in seats[]. All fields optional: section, row, number, aisle, level, type, identifier, description.

WiFi — WifiNetwork

An entry in wifiAccess[]. ssid and password required.

objects.json
// CurrencyAmount
{ "amount": "42.50", "currencyCode": "USD" }

// Location
{ "latitude": 37.784, "longitude": -122.433 }

// Seat
{ "seatSection": "A", "seatRow": "12",
  "seatNumber": "5" }

// WifiNetwork
{ "ssid": "Guest", "password": "welcome" }

Make it stick

Three habits keep semantic passes healthy:

DoSend a time zone on every date. A date without one shows the wrong time to someone in another city — and can get the pass rejected.
AvoidNever send empty strings. "venueRoom": "" is malformed content; omit the key instead. Blank values are a leading cause of a pass silently falling back to the plain layout.
DoOnly tag what's true. A tag you don't mean (a placeholder price, a fake seat) shows up as real on someone's phone. When in doubt, leave it out.
